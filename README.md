# Контур

«Контур» — учебное веб-приложение для внутреннего учёта и обработки заявок
небольшой организации. Проект выполнен в рамках производственной практики
по специальности 09.02.07 «Информационные системы и программирование»
(профессиональный модуль ПМ.02 «Осуществление интеграции программных модулей»).

Приложение позволяет регистрировать заявки, просматривать их список,
изменять данные и статус, фильтровать записи и удалять их. Интерфейс работает
без перезагрузки страницы и обменивается данными с сервером через REST API.

## Возможности

- создание заявки с названием, описанием, категорией и приоритетом;
- просмотр списка всех заявок;
- просмотр отдельной заявки по идентификатору;
- редактирование названия, описания, категории и приоритета;
- изменение статуса заявки;
- удаление заявки с подтверждением;
- фильтрация по статусу и категории;
- сброс фильтров;
- краткая статистика по текущему списку;
- автоматическое создание базы данных SQLite при первом запуске;
- понятные сообщения об ошибках на русском языке;
- адаптивный интерфейс для компьютера, планшета и телефона.

## Установка

Требуется Python 3.10 или более новая версия.

### Windows

```bash
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Linux / macOS

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Запуск

```bash
python app.py
```

После запуска приложение доступно по адресу:

```text
http://127.0.0.1:5000
```

При первом запуске автоматически создаётся файл `instance/kontur.db`
и таблица `requests`. Сервер запускается в режиме отладки Flask.

Альтернативный запуск через Flask CLI:

```bash
flask --app app run --debug
```

## Тестирование

```bash
python -m pytest
```

Более подробный вывод:

```bash
python -m pytest -v
```

Тесты используют временную базу данных, создаваемую для каждого теста,
поэтому основная база `instance/kontur.db` не изменяется.

Ожидаемый результат: **25 passed**.

## API

Базовый адрес: `/api/requests`.

| Метод | Маршрут | Назначение | Успешный ответ |
|---|---|---|---|
| GET | `/api/requests` | список заявок, фильтры `status`, `category` | 200, JSON-массив |
| GET | `/api/requests/<id>` | одна заявка по ID | 200, JSON-объект |
| POST | `/api/requests` | создание заявки | 201, созданная заявка |
| PUT | `/api/requests/<id>` | изменение данных заявки | 200, обновлённая заявка |
| PATCH | `/api/requests/<id>/status` | изменение статуса | 200, обновлённая заявка |
| DELETE | `/api/requests/<id>` | удаление заявки | 200, JSON-сообщение |

Пример создания заявки:

```json
{
    "title": "Не работает принтер",
    "description": "Принтер не печатает документы из бухгалтерии.",
    "category": "Оборудование",
    "priority": "Высокий"
}
```

Пример ответа с ошибкой валидации:

```json
{
    "error": "Название заявки не может быть пустым.",
    "details": [
        "Название заявки не может быть пустым."
    ]
}
```

Допустимые приоритеты: `Низкий`, `Средний`, `Высокий`.

Допустимые статусы: `Новая`, `В работе`, `Выполнена`, `Закрыта`.

Пример фильтрации:

```text
GET /api/requests?status=Новая&category=Оборудование
```

## Ограничения учебного проекта

- нет регистрации и авторизации пользователей;
- нет ролей и разграничения прав доступа;
- нет постраничного вывода и сортировки по произвольному полю;
- справочник категорий хранится в интерфейсе, а не в отдельной таблице БД;
- SQLite подходит для небольшой организации и учебной нагрузки, но не
  рассчитана на высокую параллельную нагрузку.

Перечисленные ограничения не мешают продемонстрировать разработку
требований, архитектуру, интеграцию модулей, отладку, тестирование
и инспектирование кода в рамках ПМ.02.
