# Интеграция программных модулей

## 1. Что понимается под интеграцией

В проекте «Контур» интеграция — это согласованная работа нескольких
программных модулей, написанных на разных языках и выполняющих разные задачи:

- HTML и CSS отвечают за представление;
- JavaScript — за действия пользователя и обмен данными;
- Fetch API — за HTTP-запросы из браузера;
- Flask — за приём запросов и формирование ответов;
- Blueprint — за модульное разделение маршрутов;
- сервисный слой — за бизнес-правила;
- модель `Request` — за структуру и валидацию данных;
- SQLite — за хранение записей.

Модули не вызывают друг друга хаотично. У каждого есть зона
ответственности, а обмен данными идёт по определённым правилам.

## 2. Flask как сторонний программный модуль

Flask установлен из PyPI и указан в `requirements.txt`:

```text
Flask==3.0.3
pytest==8.3.4
```

В коде Flask используется так:

```python
from flask import Flask, Blueprint, jsonify, render_template, request

app = Flask(__name__)
app.register_blueprint(request_bp)
```

Что даёт Flask:

- маршрутизацию URL;
- разбор JSON-тела (`request.get_json`);
- сериализацию словарей (`jsonify`);
- рендеринг HTML-шаблона (`render_template`);
- тестовый клиент для проверки запросов без запуска сервера;
- обработку HTTP-кодов и ошибок.

Flask не содержит бизнес-логики проекта. Он выступает «входной точкой»
и передаёт управление сервису.

## 3. SQLite как компонент хранения

SQLite выбрана потому, что:

- не требует отдельного сервера;
- входит в стандартную библиотеку Python (`sqlite3`);
- хранит все данные в одном файле;
- удобна для учебного проекта и небольшой организации.

Интеграция с Python:

```python
import sqlite3

connection = sqlite3.connect(db_path)
connection.row_factory = sqlite3.Row
```

`row_factory = sqlite3.Row` позволяет обращаться к полям строки по имени:
`row["title"]`, а не по индексу. Это уменьшает число ошибок при изменении
порядка колонок.

Все SQL-запросы параметризованы:

```python
connection.execute(
    "SELECT * FROM requests WHERE status = ?",
    (status,),
)
```

Значения передаются отдельным кортежем. SQL-инъекция через поле фильтра
или название заявки невозможна, потому что драйвер сам экранирует значения.

Соединение открывается на одну операцию и закрывается в `finally`:

```python
@contextmanager
def database_connection(db_path):
    connection = get_connection(db_path)
    try:
        yield connection
    finally:
        connection.close()
```

## 4. Blueprint для разделения маршрутов

Blueprint создаётся в `routes/request_routes.py`:

```python
request_bp = Blueprint(
    "requests",
    __name__,
    url_prefix="/api/requests",
)
```

Преимущества:

- все маршруты API находятся в одном модуле;
- префикс задаётся один раз;
- Blueprint можно зарегистрировать в любом приложении;
- главная страница и API не смешиваются в `app.py`.

Маршруты Blueprint:

| Метод | Правило | Функция |
|---|---|---|
| GET | `""` | `get_requests` |
| GET | `"/<int:request_id>"` | `get_request` |
| POST | `""` | `create_request` |
| PUT | `"/<int:request_id>"` | `update_request` |
| PATCH | `"/<int:request_id>/status"` | `update_request_status` |
| DELETE | `"/<int:request_id>"` | `delete_request` |

Конвертер `<int:request_id>` принимает только целые числа. Строка вместо
числа приводит к стандартному ответу 404, который для адресов `/api/`
преобразуется в JSON обработчиком приложения.

## 5. Fetch API и JSON

JavaScript отправляет запросы функцией `apiRequest()` в `static/js/app.js`.
Она:

1. добавляет заголовок `Accept: application/json`;
2. при наличии тела добавляет `Content-Type: application/json`;
3. вызывает `fetch`;
4. читает ответ как текст;
5. разбирает текст через `JSON.parse`;
6. при статусе не 2xx выбрасывает ошибку с сообщением сервера;
7. возвращает данные вызывающей функции.

Пример создания заявки:

```javascript
const created = await apiRequest("/api/requests", {
    method: "POST",
    body: JSON.stringify({
        title: "Не работает принтер",
        description: "Принтер не печатает документы.",
        category: "Оборудование",
        priority: "Высокий",
    }),
});
```

JSON используется как единый формат обмена. Пример ответа:

```json
{
    "id": 1,
    "title": "Не работает принтер",
    "description": "Принтер не печатает документы.",
    "category": "Оборудование",
    "priority": "Высокий",
    "status": "Новая",
    "created_at": "2026-11-07 10:15:00",
    "updated_at": "2026-11-07 10:15:00"
}
```

Для корректного отображения кириллицы в `create_app()` установлено:

```python
app.json.ensure_ascii = False
```

Без этой настройки Flask вернул бы `\u041d\u043e\u0432\u0430\u044f` вместо
слова «Новая». JSON остаётся валидным, но читать его в DevTools неудобно.

## 6. HTTP-методы

| Метод | Где используется | Смысл |
|---|---|---|
| GET | загрузка списка и одной заявки | получить данные, не изменяя их |
| POST | создание заявки | создать новую запись |
| PUT | редактирование заявки | заменить основные данные |
| PATCH | изменение статуса | изменить одно поле |
| DELETE | удаление заявки | удалить запись |

Коды ответов:

- `200 OK` — успешное получение, изменение или удаление;
- `201 Created` — заявка создана;
- `400 Bad Request` — ошибка валидации или некорректный JSON;
- `404 Not Found` — заявка или маршрут не найдены;
- `405 Method Not Allowed` — неподдерживаемый метод;
- `500 Internal Server Error` — непредвиденная ошибка сервера.

## 7. Полная цепочка интеграции

### 7.1. Создание заявки

```text
1. Пользователь заполняет форму в index.html и нажимает «Создать заявку».
2. app.js перехватывает submit, проверяет title и category.
3. apiRequest() отправляет POST /api/requests с JSON.
4. Flask направляет запрос в create_request().
5. create_request() читает JSON через request.get_json(silent=True).
6. RequestService.create_request() создаёт объект Request.
7. Request.validate() проверяет поля.
8. RequestRepository.create() выполняет параметризованный INSERT.
9. SQLite сохраняет строку и возвращает lastrowid.
10. Репозиторий повторно читает заявку по ID.
11. Сервис возвращает объект Request.
12. Маршрут вызывает to_dict() и jsonify(), возвращает HTTP 201.
13. app.js получает JSON, очищает форму, показывает уведомление.
14. loadRequests() заново запрашивает список и перерисовывает карточки.
```

### 7.2. Получение списка с фильтрами

```text
1. Пользователь выбирает статус или категорию.
2. app.js собирает URLSearchParams.
3. GET /api/requests?status=...&category=...
4. Flask вызывает RequestService.get_all_requests().
5. Сервис проверяет допустимость статуса.
6. RequestRepository.get_all() добавляет условия WHERE.
7. SQLite возвращает строки.
8. Репозиторий превращает строки в Request.
9. Маршрут сериализует список в JSON-массив.
10. app.js перерисовывает список и статистику.
```

### 7.3. Изменение статуса

```text
1. Пользователь выбирает статус в select карточки.
2. app.js отправляет PATCH /api/requests/<id>/status.
3. Flask проверяет наличие поля status.
4. Сервис проверяет существование заявки и допустимость статуса.
5. Репозиторий выполняет UPDATE с новым статусом и updated_at.
6. API возвращает обновлённую заявку.
7. Список перезагружается с учётом текущих фильтров.
```

### 7.4. Удаление

```text
1. Пользователь нажимает «Удалить».
2. app.js показывает window.confirm.
3. При подтверждении отправляется DELETE /api/requests/<id>.
4. Репозиторий выполняет DELETE.
5. Если строка не найдена — HTTP 404.
6. При успехе API возвращает сообщение и ID.
7. Список обновляется.
```

## 8. Интеграционное тестирование

Интеграция проверялась несколькими способами.

### 8.1. Браузер

Приложение запускалось командой:

```bash
python app.py
```

Проверялись:

- загрузка главной страницы;
- создание заявки через форму;
- редактирование через диалоговое окно;
- смена статуса;
- удаление;
- фильтры и сброс;
- поведение при пустом списке.

### 8.2. Developer Tools → Network

В браузере контролировались:

- URL запроса;
- метод;
- заголовки `Content-Type` и `Accept`;
- тело запроса;
- код ответа;
- тело ответа в формате JSON;
- время выполнения.

Это позволяло отделить ошибку интерфейса от ошибки API.

### 8.3. Flask test client и pytest

Тесты в `tests/test_api.py` обращаются к приложению без реального сетевого
сервера:

```python
response = client.post("/api/requests", json={...})
assert response.status_code == 201
```

Так проверяется вся цепочка «маршрут → сервис → репозиторий → SQLite →
JSON-ответ» на временной базе данных.

Команда запуска:

```bash
python -m pytest
```

Результат: 25 тестов пройдено.

## 9. Совместимость и типичные точки интеграции

| Точка | Требование | Реализация |
|---|---|---|
| URL | одинаковый путь на клиенте и сервере | `API_URL = "/api/requests"` и префикс Blueprint |
| Метод | соответствует операции | GET, POST, PUT, PATCH, DELETE |
| Формат тела | JSON | `JSON.stringify` и `request.get_json` |
| Кодировка | UTF-8 | Flask и SQLite работают со строками Unicode |
| Ответ | JSON | `jsonify` и `JSON.parse` |
| Ошибки | единый формат | поля `error` и `details` |
| Тестовая БД | не затрагивать основную | `tmp_path` в фикстуре `app` |

## 10. Вывод

Интеграция модулей в проекте выполнена по схеме
«интерфейс → HTTP/JSON → маршрут → сервис → модель/репозиторий → SQLite».
Каждый модуль можно заменить или протестировать отдельно, а REST API
выступает стабильным контрактом между frontend и backend. Именно эта
цепочка является основным результатом практики по ПМ.02.
