# Тестирование проекта «Контур»

## 1. Виды тестирования

В проекте использованы:

- **модульное тестирование модели** — проверка `Request.validate()`
  и `Request.to_dict()`;
- **интеграционное тестирование API** — проверка цепочки
  «Flask → сервис → репозиторий → SQLite → JSON»;
- **ручная проверка интерфейса** — работа с формой, фильтрами,
  диалогом редактирования и уведомлениями в браузере;
- **проверка ответов через Flask test client** — без запуска сетевого
  сервера.

Автоматические тесты находятся в папке `tests/`.

## 2. Окружение и запуск

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

Запуск всех тестов:

```bash
python -m pytest
```

Подробный вывод:

```bash
python -m pytest -v
```

Запуск только модели:

```bash
python -m pytest tests/test_model.py -v
```

Запуск только API:

```bash
python -m pytest tests/test_api.py -v
```

## 3. Изоляция тестовой базы

В `tests/conftest.py` определена фикстура `app`:

```python
@pytest.fixture()
def app(tmp_path):
    database_path = tmp_path / "test_kontur.db"
    application = create_app(
        {
            "TESTING": True,
            "DATABASE_PATH": str(database_path),
        }
    )
    yield application
```

Каждый тест получает:

- новый экземпляр Flask-приложения;
- новый временный файл SQLite в папке `tmp_path`;
- чистую таблицу `requests`.

Основная база `instance/kontur.db` при тестировании не изменяется.

Другие фикстуры:

| Фикстура | Назначение |
|---|---|
| `app` | тестовое приложение с временной БД |
| `client` | Flask test client для HTTP-запросов |
| `sample_request` | заранее созданная корректная заявка |

## 4. Автоматические тесты

### 4.1. tests/test_model.py — 7 тестов

| Тест | Что проверяет |
|---|---|
| `test_valid_request_passes_validation` | корректная заявка проходит валидацию |
| `test_empty_title_raises_validation_error` | пустое название отклоняется |
| `test_missing_category_raises_validation_error` | отсутствие категории отклоняется |
| `test_invalid_priority_raises_validation_error` | неверный приоритет отклоняется |
| `test_invalid_status_raises_validation_error` | неверный статус отклоняется |
| `test_to_dict_returns_all_fields` | преобразование в словарь |
| `test_from_row_creates_request` | создание модели из строки БД |

### 4.2. tests/test_api.py — 18 тестов

| Тест | Что проверяет |
|---|---|
| `test_get_requests_returns_empty_list` | пустой список |
| `test_create_request_success` | создание заявки, HTTP 201 |
| `test_create_request_without_title` | пустое название, HTTP 400 |
| `test_create_request_without_category` | нет категории, HTTP 400 |
| `test_create_request_with_invalid_priority` | неверный приоритет |
| `test_create_request_with_invalid_json` | некорректный JSON |
| `test_get_request_by_id` | получение по ID |
| `test_get_missing_request_returns_404` | несуществующая заявка |
| `test_update_request_status` | смена статуса через PATCH |
| `test_update_request_with_invalid_status` | недопустимый статус |
| `test_update_request_status_without_field` | PATCH без поля `status` |
| `test_update_request_data` | редактирование через PUT |
| `test_delete_request` | удаление существующей заявки |
| `test_delete_missing_request_returns_404` | удаление несуществующей |
| `test_filter_requests_by_status` | фильтр по статусу |
| `test_filter_requests_by_category` | фильтр по категории |

Итого: **7 + 18 = 25 автоматических тестов**.

## 5. Тестовые сценарии

| № | Сценарий | Входные данные | Ожидаемый результат | Фактический результат |
|---|---|---|---|---|
| 1 | Создание корректной заявки | JSON: `title = "Не работает принтер"`, `description = "Принтер не печатает документы."`, `category = "Оборудование"`, `priority = "Высокий"` | HTTP 201, заявка сохранена, статус `Новая`, заполнены `id`, `created_at` | Совпадает: HTTP 201, `id = 1`, статус `Новая` |
| 2 | Создание заявки с пустым названием | `title = "   "`, категория указана | HTTP 400, сообщение «Название заявки не может быть пустым.» | Совпадает: HTTP 400, текст ошибки получен |
| 3 | Создание без категории | `title = "Настроить почту"`, `category = ""` | HTTP 400, сообщение о необходимости категории | Совпадает: HTTP 400, текст ошибки получен |
| 4 | Создание с недопустимым приоритетом | `priority = "Критический"` | HTTP 400, сообщение «Недопустимый приоритет...» | Совпадает: HTTP 400 |
| 5 | Получение списка заявок | GET `/api/requests` после создания двух заявок | HTTP 200, JSON-массив из двух элементов | Совпадает: 2 заявки, порядок от новых к старым |
| 6 | Фильтрация по статусу | Созданы две заявки; вторая переведена в `В работе`; запрос `?status=В работе` | HTTP 200, в массиве только вторая заявка | Совпадает: 1 заявка со статусом `В работе` |
| 7 | Фильтрация по категории | Заявки в категориях `Оборудование` и `Программное обеспечение`; запрос `?category=Программное обеспечение` | HTTP 200, только заявка нужной категории | Совпадает: 1 заявка |
| 8 | Получение заявки по ID | GET `/api/requests/1` | HTTP 200, поля соответствуют созданной заявке | Совпадает: HTTP 200, `title = "Не работает принтер"` |
| 9 | Получение несуществующей заявки | GET `/api/requests/9999` | HTTP 404, JSON с сообщением | Совпадает: HTTP 404, «Заявка с ID 9999 не найдена.» |
| 10 | Изменение статуса | PATCH `/api/requests/1/status`, `{"status": "В работе"}` | HTTP 200, статус изменён, `updated_at` обновлён | Совпадает: статус `В работе` подтверждён повторным GET |
| 11 | Изменение на недопустимый статус | PATCH с `{"status": "Отложена"}` | HTTP 400, сообщение о недопустимом статусе | Совпадает: HTTP 400 |
| 12 | Изменение на корректный статус | PATCH с `{"status": "Выполнена"}` | HTTP 200, статус `Выполнена` | Совпадает |
| 13 | Редактирование заявки | PUT `/api/requests/1` с новым названием «Заменить картридж» и приоритетом `Средний` | HTTP 200, поля изменены, статус сохранён | Совпадает: новые данные возвращены, статус `Новая` |
| 14 | Удаление заявки | DELETE `/api/requests/1` | HTTP 200, сообщение «Заявка успешно удалена.», повторный GET даёт 404 | Совпадает |
| 15 | Удаление несуществующей заявки | DELETE `/api/requests/9999` | HTTP 404, JSON с сообщением | Совпадает: HTTP 404 |
| 16 | Некорректный JSON | POST с телом `{"title": "Некорректный JSON"` | HTTP 400, сообщение «Некорректный JSON...» | Совпадает: HTTP 400 |

Дополнительно вручную проверены:

- отправка формы с пустым названием — появляется уведомление, запрос
  не отправляется;
- отправка формы без категории — появляется уведомление, фокус переходит
  на поле категории;
- пустой список — отображается сообщение «Заявок пока нет...»;
- фильтр без совпадений — отображается сообщение
  «По выбранным фильтрам заявок не найдено...»;
- отмена удаления — заявка остаётся в списке;
- ошибка соединения с сервером — появляется понятное уведомление.

## 7. Что покрыто и что не покрыто

Покрыто автоматическими тестами:

- правила валидации модели;
- коды ответов и JSON API;
- создание, чтение, изменение, смена статуса и удаление;
- фильтрация по статусу и категории;
- обработка некорректного JSON, неверного статуса и отсутствующих записей;
- изоляция тестовой базы.

Не покрыто автоматическими тестами:

- визуальное оформление и адаптивность;
- работа диалогового окна в конкретном браузере;
- уведомления и анимации;
- одновременная работа нескольких пользователей.

Эти пункты проверялись вручную и не требуют сложных инструментов
для учебного проекта. При развитии проекта их можно покрыть
UI-тестами (например, Playwright), но это выходит за рамки ПМ.02
в выбранном объёме.
